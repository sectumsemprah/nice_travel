## 0. 项目基线与 OpenSpec 初始化

### 0.1 补齐项目上下文

- 任务目标：建立项目目标、技术栈、架构边界、测试命令和部署约束的唯一事实来源。
- 影响范围：`openspec/project.md`、`AGENTS.md` 或 `openspec/AGENTS.md`。
- 实施要点：根据本提案确认的技术路线编写项目级约定，明确 OpenSpec 工作流、中文文档规则、代码风格、CI 命令和安全边界。
- 验收标准：项目目标、技术栈、架构分层、lint/format/test/build、部署环境、密钥管理均有明确说明。
- 验证方法：人工审阅 `openspec/project.md` 与 AGENTS 文档，确认不存在阻断级空白。
- 回滚方式：删除或还原新增项目基线文档。

### 0.2 初始化 GitHub 开源资料

- 任务目标：形成可发布到 GitHub 的基础仓库材料。
- 影响范围：`README.md`、`LICENSE`、`CONTRIBUTING.md`、`SECURITY.md`、`.env.example`、`.github/workflows/*`。
- 实施要点：编写项目介绍、快速开始、路线图、贡献流程、安全报告方式和环境变量示例，创建基础 CI。
- 验收标准：新贡献者能根据 README 理解项目并启动开发环境；CI 覆盖 lint、type-check、test、build。
- 验证方法：执行 README 中的安装与启动步骤；执行 CI 对应本地命令。
- 回滚方式：删除新增文档与 CI 配置。

## 1. 基础应用骨架

### 1.1 创建 Web 应用与工程结构

- 任务目标：建立可运行的 Web 应用骨架和分层目录。
- 影响范围：`apps/web`、`packages/domain`、`packages/providers`、`packages/shared`、根工作区配置。
- 实施要点：采用 Next.js + TypeScript，建立 presentation、application、domain、infrastructure、jobs、observability 分层约定。
- 验收标准：应用可本地启动；类型检查、格式化和基础构建可通过。
- 验证方法：执行安装、lint、type-check、build、启动命令。
- 回滚方式：移除新增应用骨架与工作区配置。

### 1.2 建立数据库模型与迁移

- 任务目标：支持旅行项目、偏好、来源、洞察、行程、路线、素材、相册和任务状态的持久化。
- 影响范围：Prisma schema、数据库迁移、领域模型。
- 实施要点：实现 User、Trip、PreferenceProfile、TravelSource、TravelInsight、Place、ItineraryDay、ItineraryItem、RouteSnapshot、MemoryAsset、MemoryAlbum、Job。
- 验收标准：迁移可执行、可回滚；核心表含资源归属字段、创建/更新时间和必要索引。
- 验证方法：执行数据库迁移、回滚迁移、模型单元测试。
- 回滚方式：执行迁移回滚并移除模型变更。

## 2. 旅行攻略生成

### 2.1 实现旅行项目与偏好管理

- 任务目标：用户可创建和管理旅行项目及个性化偏好。
- 影响范围：Trip API、Preference API、前端表单、权限校验。
- 实施要点：实现创建、详情、编辑、删除；校验项目归属；表单包含目的地、日期、预算、同行人、兴趣、节奏、交通、禁忌。
- 验收标准：用户只能访问自己的项目；无效输入返回清晰错误。
- 验证方法：执行 API 单元/集成测试，覆盖创建、编辑、越权访问、无效输入。
- 回滚方式：回退相关 API、页面和数据库迁移。

### 2.2 实现合规信息源 Provider

- 任务目标：支持从合规渠道检索或导入旅行信息。
- 影响范围：Source Provider 接口、检索任务、TravelSource 存储。
- 实施要点：定义 Provider 接口；首版支持手动链接/文本导入和可配置公开搜索 Provider；记录来源、状态、错误和引用。
- 验收标准：系统不包含绕过平台限制的逻辑；所有候选信息保留来源引用。
- 验证方法：执行 Provider 单元测试、失败重试测试和合规边界人工审查。
- 回滚方式：禁用对应 Provider 配置并回退代码。

### 2.3 实现洞察提取与候选地点筛选

- 任务目标：从候选信息中生成结构化地点洞察和推荐依据。
- 影响范围：TravelInsight 服务、LLM Provider、地点归一化逻辑。
- 实施要点：抽取地点、推荐理由、限制条件、避坑提示、热度、置信度；保留来源引用；对 LLM 输入做敏感信息最小化。
- 验收标准：洞察结构稳定、可追溯；信息不足时显式失败或部分成功。
- 验证方法：执行提取逻辑单元测试、样例输入快照测试、LLM Provider mock 测试。
- 回滚方式：关闭洞察任务入口并保留原始来源记录。

### 2.4 实现个性化行程生成

- 任务目标：根据偏好、地点、时间、距离和预算生成多日行程。
- 影响范围：Itinerary 服务、生成任务、前端行程视图。
- 实施要点：实现约束评分、按天编排、冲突标记、版本保存和用户编辑。
- 验收标准：行程节点包含地点、时间、停留时长、推荐理由和风险提示；用户可编辑并保存。
- 验证方法：执行生成规则单元测试、端到端关键用例、冲突场景测试。
- 回滚方式：回退生成服务与页面，保留用户已有 Trip 数据。

## 3. 路径图与地图能力

### 3.1 实现地图 Provider 抽象

- 任务目标：隔离高德/百度/Mapbox 等地图服务差异。
- 影响范围：Map Provider 接口、配置、路线计算服务。
- 实施要点：定义地理编码、距离估算、路线计算、静态图渲染能力；支持 Provider 不可用降级。
- 验收标准：更换 Provider 不影响业务层；失败时可降级为地点顺序列表。
- 验证方法：执行 Provider mock 测试、异常降级测试。
- 回滚方式：禁用地图功能入口或切换到 mock Provider。

### 3.2 生成路径图与路线快照

- 任务目标：用户可基于确认行程生成路径图。
- 影响范围：RouteSnapshot 模型、路线 API、前端路径图视图。
- 实施要点：按行程顺序计算路径，保存距离、耗时、路径点、Provider 和渲染产物。
- 验收标准：路径图可预览；路线元数据可查询；地图不可用时展示降级信息。
- 验证方法：执行路线 API 测试、地图降级测试、前端视图检查。
- 回滚方式：删除路径图入口并保留行程列表。

## 4. 旅行记忆与电子相册

### 4.1 实现素材上传与管理

- 任务目标：用户可上传和管理旅行照片、文字、时间与地点信息。
- 影响范围：MemoryAsset API、对象存储、缩略图任务、素材管理界面。
- 实施要点：实现上传、缩略图、元数据解析、删除/软删除、资源归属校验和容量限制。
- 验收标准：素材默认私有；越权访问被拒绝；删除后关联导出产物标记过期。
- 验证方法：执行上传 API 测试、权限测试、容量限制测试、对象存储 mock 测试。
- 回滚方式：禁用上传入口，清理新增存储对象和数据库记录。

### 4.2 实现电子相册生成

- 任务目标：基于素材、行程和地点轨迹生成可预览的旅行回忆页。
- 影响范围：MemoryAlbum 服务、相册页面、导出任务。
- 实施要点：生成封面、时间线、地点章节、图片排版和文案；保存版本；支持重新生成。
- 验收标准：相册可预览、可重新生成、可追溯输入素材版本。
- 验证方法：执行相册生成单元测试、快照测试、关键页面视觉检查。
- 回滚方式：关闭相册生成入口并保留原始素材。

## 5. 分享、导出与权限

### 5.1 实现受控分享链接

- 任务目标：用户可安全分享只读行程或电子相册。
- 影响范围：ShareToken 模型、分享 API、公开只读页面。
- 实施要点：生成不可猜测令牌，支持过期、撤销、只读访问和访问日志。
- 验收标准：未授权用户不能访问私有内容；撤销后链接立即失效。
- 验证方法：执行分享权限测试、过期测试、撤销测试。
- 回滚方式：禁用分享入口并删除分享令牌。

### 5.2 实现导出能力

- 任务目标：支持将行程、路径图和相册导出为网页包或图片集。
- 影响范围：Export API、导出任务、对象存储、前端下载入口。
- 实施要点：异步生成导出产物，记录状态、失败原因和产物 URL；PDF 作为后续增强。
- 验收标准：导出状态可查询；失败可重试；产物不泄露未授权数据。
- 验证方法：执行导出任务测试、权限测试、失败重试测试。
- 回滚方式：关闭导出入口并清理导出产物。
